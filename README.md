# InsightForge

Multi-tenant venture discovery platform. Runs two engagement tiers per client business:

- **VDOS** (Venture Discovery Operating System) — the full 11-stage gated methodology (Stage 0 Assumption Destruction + Stages 1–11, validated by 6 ASQ evidentiary instruments), persisted per-stage so engagements are resumable and auditable.
- **FORGE Lite** — the original single-shot 10-step intake → one Claude call → one report flow, kept as a faster/cheaper tier.

Every record is scoped to a `business_id` tenant (see `lib/db/scoped.ts` / `lib/tenant.ts`), so client businesses never see each other's data.

## Getting Started (first deploy)

These steps must be run once, against your own Supabase project — they can't be run from a sandboxed dev environment because they require live `SUPABASE_SERVICE_ROLE_KEY` credentials.

1. **Run the schema migrations**, in this exact order, in the Supabase SQL editor:
   1. `supabase/schema.sql`
   2. `supabase/migrations/0002_vdos.sql` (depends on `discovery_sessions` already existing from step 1 — it adds the legacy `business_id` bridge column plus all VDOS tables)

2. **Set `.env.local`** with every variable from `.env.example`, including a freshly generated session secret:
   ```bash
   cp .env.example .env.local
   openssl rand -hex 32   # paste the output in as SESSION_SECRET
   ```

3. **Install dependencies** (this pulls in `tsx`, used to run the one-off seed scripts below):
   ```bash
   npm install
   ```

4. **Create your first consultant login** (there is no signup UI — auth is invite/admin-provisioned):
   ```bash
   npm run seed:consultant -- you@example.com 'a-strong-password' "Your Name" admin
   ```
   `admin` role sees every business with no extra access grant needed; use `consultant` for a role scoped to specific businesses via `consultant_business_access`.

5. **Import PrimeTurf's completed VDOS engagement** (real client data, parsed from their 7 reference reports — not regenerated by Claude):
   ```bash
   npm run seed:primeturf
   ```

6. **Import the second seeded business** (Ready & Rooted, NZ — see `scripts/seed-readyrooted.ts`):
   ```bash
   npm run seed:readyrooted
   ```

7. **Run the app and verify**:
   ```bash
   npm run dev
   ```
   Log in at `/command/login`, confirm both businesses appear in the business switcher, and that `/vdos-blueprint/[engagementId]` renders for each. Switching the active business should show only that business's engagements — proving tenant isolation.

## Scripts

| Script | Purpose |
|---|---|
| `npm run dev` / `build` / `start` / `lint` | Standard Next.js commands |
| `npm run seed:consultant -- <email> <password> <displayName> [role]` | Provision a consultant login (`role` defaults to `admin`) |
| `npm run seed:primeturf` | Idempotently import PrimeTurf's completed VDOS engagement |
| `npm run seed:readyrooted` | Idempotently import the Ready & Rooted (NZ) VDOS engagement |
